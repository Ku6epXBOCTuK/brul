# Язык импортов

Статус: stable. Канон языка: парсер импортов проверяется на этой спеке.

Принципы — [architecture.md §Решения](../dev/architecture.md#решения).

## Идея

Компонент переиспользуется, когда его файл объявлен в блоке `<use>`. Импорт —
декларация файла, а не инструкция скрипта: имя становится доступно разметке как
компонент. Ресурс объявляется там же: имя становится доступно разметке как
источник `Image`.

Блок `<use>` — часть структуры SFC, см. [markup.md](markup.md) §«Файлы и
импорты».

## Семантика

- Импорт компонента — `import Name from "./path";`, другого синтаксиса импорта
  нет. Путь относителен файла, в котором стоит `<use>`; расширение `.brul`
  подставляется, если его не указали.
- Ресурс — `resource Name from "./path.png";`. Путь тоже относителен файла, но
  расширение входит в путь и не подставляется.
- Ресурс — только PNG: байты файла зашиваются в бинарь, поэтому файл обязан
  существовать и начинаться с PNG-сигнатуры. Иначе сборка падает с ошибкой, как
  и на дубле имени ресурса в одном блоке.
- Имя ресурса доступно разметке этого файла как источник `Image` (например,
  `Image (icon) { check }`); компонентом и значением скрипта оно не является.
- Найденный компонент разбирается целиком, его собственные `<use>` дают цепочку;
  цикл — ошибка загрузки с путём цепочки.
