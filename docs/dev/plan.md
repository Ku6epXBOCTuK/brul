# План

Маршрут срезами: один срез — один коммит и один ревью. Процесс и бюджет среза —
[workflow.md](workflow.md); здесь только очередь. Срез закрыт, когда зелёные
`cargo clippy --workspace -- -D warnings` и `cargo test --workspace`; закрытая
строка удаляется из файла, историю хранит git. Текущий срез — задача в трекере
`BRUL`.

## Фаза 1 — реактивное ядро

- 1.1 — Criterion: цепочка, ромб, много подписчиков, батчи; база для регрессий,
  без сравнения с чужими движками.

Готово, когда: контракт [реактивного ядра](architecture.md#реактивное-ядро)
проходит на текущей реализации, а бенчмарки дают базу для регрессий.

## Фаза 2 — рендер без DSL

- 2.1 — текст: `cosmic-text`, атлас глифов, кириллица, эмодзи, DPI.
- 2.2 — прямоугольники: радиус, граница, заливка.
- 2.3 — картинки: PNG, tint.
- 2.4 — окно: frameless, прозрачность, drag за хедер, Esc, DPI.
- 2.5 — лейаут: measure → place, Row/Column, padding/spacing, stretch, проценты,
  абсолют; только целые px.
- 2.6 — виджеты `View`/`Text`/`Image`, hit-test, события, снапшоты состояний.
- 2.7 — реактивность → рендер: batch → flush → перерисовка только
  dirty-виджетов.
- 2.8 — пикер на чистом Rust API: хедер, список из TOML, чекбоксы, темы, запуск
  браузера.

Готово, когда: пикер открывает реальные ссылки без DSL.

## Фаза 3 — DSL

- 3.1 — парсер разметки по [markup.md](../lang/markup.md), ошибки с позицией.
- 3.2 — парсер стилей → снапшоты, валидация свойств и тем.
- 3.3 — парсер скрипта + интерпретатор.
- 3.4 — кодеген `.brul` → Rust: дерево виджетов и update-функции.
- 3.5 — интеграция: компонент из спеки работает в окне.

Готово, когда: путь `.brul` → код → экран пройден.

## Фаза 4 — MVP

bropicker:

- 4.1 — логика пикера без UI: config, launcher, реестр, маппинг доменов.
- 4.2 — главное окно на DSL, паритет с текущей версией.
- 4.3 — окно настроек: список доменов, удаление записи, флаги.
- 4.4 — системная интеграция: регистрация обработчиком ссылок, иконка.

Панель служб:

- 4.5 — слой служб на Rust: `svc list --json`, старт/стоп/рестарт, хвост лога.
- 4.6 — окно на DSL: список, статусы, кнопки, «запустить все Manual».
- 4.7 — обновление по `every` и хвост лога выбранной службы.

Готово, когда:

- 4.8 — замеры: холодный старт, DPI, ошибки конфига; 1–2 недели ежедневного
  использования обеих версий.

## Открытые решения

| Вопрос                                     | Шаг      | Рекомендация            |
| ------------------------------------------ | -------- | ----------------------- |
| Кодеген: build.rs-генератор или proc-macro | 3.4      | офлайн-генератор первым |

## После MVP

- Зарезервированные метрики текста (union shaping): текст шейпится по самому
  широкому весу из состояний, поэтому `font-weight` не требует фиксированного
  размера `Text`. Сейчас он разрешён только на `Text` с заданными `width` и
  `height` ([style.md](../lang/style.md#текстовые-метрики)).
- Follow-режим хвоста лога, фильтр по логу, иконка панели служб в трее.
