# План

Маршрут задачами: одна задача — один коммит и один ревью. Процесс и бюджет —
[workflow.md](workflow.md); здесь только очередь. Задача закрыта, когда зелёные
`cargo clippy --workspace -- -D warnings`, `cargo nextest run --workspace` и
`cargo test --workspace --doc`; выполненный пункт отмечается `[x]`, историю
хранит git. Текущая задача — первый неотмеченный пункт.

## Приоритеты

Порядок работ. Критерий — что дешевле сделать до того, как оно подорожает:
сначала снимается сцепление, потом ежедневный налог, потом читаемость, потом
косметика.

1. **Граница приложений** — BRUL-302, BRUL-303. Пока приложение знает внутренние
   крейты, каждая новая фича удорожает вынос.
2. **Конвейер свойств** — BRUL-304, BRUL-305, BRUL-306. Гейт note-obs: поле
   ввода упрётся в него первым.
3. **Читаемость генерации** — BRUL-307, BRUL-308, BRUL-309. После конвейера: те
   же `emit/*` и `styles.rs`, иначе переписывать дважды.
4. **note-obs** — сначала пробелы движка (BRUL-329…BRUL-334), потом само
   приложение (BRUL-335…BRUL-339).
5. **Rust-way на чекпоинте** — BRUL-310, BRUL-280–283. После первого приложения
   фазы, до следующего: замер `just debt`, затем долг.
6. **Панель служб** — BRUL-193, BRUL-194, BRUL-195 (BRUL-235).
7. **Замеры и готовность** — BRUL-232, BRUL-196 (BRUL-234).
8. **Вынос приложений** — BRUL-311, после BRUL-196, когда API перестанет
   дёргаться.

Фоном, а не фазой: шероховатости приложений (BRUL-296, BRUL-297 и новые).
Находка становится задачей в момент обнаружения; блокирующая чинится сразу.
Найденное при чтении движка и отложенное: BRUL-340, BRUL-341.

## 1. Граница приложений (BRUL-276)

Приложение перестаёт зависеть от того, как BRUL разложен на крейты. Это
предусловие выноса (BRUL-311) и две задачи, а не репозиторная операция.

- [x] BRUL-302 — приложение импортирует `brul-gui` и `brul-codegen` напрямую:
  фасад не отдаёт нужное.
- [x] BRUL-303 — `build.rs` каждого приложения повторяет обвязку кодогена.

## 2. Конвейер свойств (BRUL-276)

Драйвер — будущее поле ввода. Решение о месте стиля принимается первым: от него
зависит, где вообще живёт знание о свойстве.

- [x] BRUL-313 — модель и каскад стиля живут в `brul-style`, а не в парсере.
- [x] BRUL-306 — новое свойство стиля требует пяти согласованных правок.
- [x] BRUL-304 — стиль в сгенерированном коде запечён литералом: оставить или
  резолвить таблицей.
- [x] BRUL-305 — конвертация значения выбирается по `Kind`, а не по типу.
- [x] BRUL-314 — свойство объявляется тремя списками: вариант `Kind`, запись
  `SPECS` и список всех свойств.

После BRUL-314 новое свойство — вариант `Kind` и строка таблицы плюс механика
(paint, лейаут, доки), а не пять синхронных правок.

## 3. Читаемость генерации (BRUL-276)

Только после конвейера: оба блока трогают эмиттер и резолв стилей.

- [x] BRUL-307 — скрипт запекается в модуль AST-литералом.
- [x] BRUL-308 — каждый узел обёрнут в `let widgetN = …; widgetN`.
- [x] BRUL-309 — имена сгенерированных функций нумерованные.

## 4. Фиксы и фичи BRUL для note-obs (BRUL-328)

Окно живёт в трее, а фон меняет то, что видно на экране. Без этих пробелов
приложение не повторить: всё это правки движка со спекой в `docs/lang`.

- [x] BRUL-250 — поле ввода текста: каретка, выделение, IME, буфер.
- [x] BRUL-329 — окно не скрывается и не показывается: параметр `visible`,
  `showWindow()` и `hideWindow()`.
- [x] BRUL-330 — крестик окна нельзя перехватить: событие `on close`.
- [x] BRUL-331 — клавиши окна не несут модификаторов: Ctrl+Enter не отличить от
  Enter.
- [x] BRUL-332 — окно не задаёт позицию и не центрируется.
- [x] BRUL-333 — окно нельзя поднять поверх остальных: `setAlwaysOnTop(bool)`.
- [x] BRUL-334 — состояние фонового потока не протолкнуть в DSL: `Handle` и
  пробуждение цикла.

## 5. note-obs (BRUL-328)

Окно целиком на DSL; Rust держит трей, OBS WebSocket, IPC, AFK, конфиг и логи.
Эталон — egui-версия в `qol/note-to-obs`.

- [x] BRUL-335 — каркас: пакет `apps/note-obs`, `build.rs`, CLI, конфиг, первое
  окно с кнопками на заглушках.
- [x] BRUL-336 — OBS: воркер на tokio и `obws`, коннект с таймаутом, разные
  ошибки, проверка сцены.
- [ ] BRUL-337 — пресеты и AFK: сетка, чекбокс, поле, idle через `windows-sys`,
  сохранение через `toml_edit`.
- [ ] BRUL-338 — трей и live: меню, скрытие по Esc и крестику, `--tray`, рамка и
  `setAlwaysOnTop`.
- [ ] BRUL-339 — паритет с эталоном и тесты конфига и команд хоста.

## 6. Rust-way на чекпоинте (BRUL-276)

После работающего note-obs и до панели служб: замер `just debt` и по одной
задаче на находку. Распилы идут после конвейера свойств, иначе пилить придётся
дважды.

- [ ] BRUL-310 — публичные ошибки: `String` вместо типа.
- [ ] BRUL-280 — `brul-gui/src/widget.rs`.
- [ ] BRUL-282 — `brul-window/src/tree.rs`.
- [ ] BRUL-283 — `brul-script/src/eval.rs` и `brul-gui/src/layout.rs`.
- [ ] BRUL-281 — `brul-codegen/src/runtime.rs`; последним, после BRUL-307 он
  усохнет.

Отложенное в BRUL-108 (BRUL-109, BRUL-112, BRUL-113, BRUL-140, BRUL-144 и
остальные) пересматривается по опыту эксплуатации, а не заранее.

## 9. Вынос приложений

- [ ] BRUL-311 — приложения ведутся в репозитории BRUL: история и релизы
  смешаны.

Механика: `git subtree split -P apps/bropicker` сохраняет историю, дальше
приложение берёт BRUL тегом на релиз, а не путём в рабочей копии. Порядок
зависимостей вынесенного приложения решается при выносе.

## После MVP

- Зарезервированные метрики текста (union shaping): текст шейпится по самому
  широкому весу из состояний, поэтому `font-weight` не требует фиксированного
  размера `Text`. Сейчас он разрешён только на `Text` с заданными `width` и
  `height` ([style.md](../lang/style.md#текстовые-метрики)).
- Follow-режим хвоста лога, фильтр по логу, иконка панели служб в трее.
