# aurora

Пример шейдерного эффекта из стиля: сетка 2×2, в первой ячейке — сияние, которое
рисуется WGSL-шейдером. Эффект объявляется в `window.brul`, параметры приходят
из скрипта через биндинг, а шейдер лежит отдельным файлом.

## Запуск

Из корня рабочей копии:

```powershell
just aurora
```

Это рецепт `aurora-gpu`: он выставляет `BRUL_EXAMPLE_BACKEND = 'gpu'` и
запускает пример. Софтверный бэкенд не показывает эффекты, поэтому GPU — режим
по умолчанию для этого примера. Явно его можно вызвать так:

```powershell
just aurora-gpu
just aurora-software
```

То же без just — `$env:BRUL_EXAMPLE_BACKEND = 'gpu'; cargo run -p aurora`.
Значения переменной — `software` и `gpu`. Как и в `hello`, приложение само
записывает выбранный бэкенд в `WindowConfig.backend` до `run_generated`. Поле
ввода в правой нижней ячейке меняет `phase`: число становится аргументом эффекта
и обновляет uniform-слоты без пересборки окна.

## Что внутри

| Файл               | Роль                                                       |
| ------------------ | ---------------------------------------------------------- |
| `src/window.brul`  | окно, сетка, правило `effect`, скрипт со `setPhase`        |
| `src/aurora.wgsl`  | шейдер: `fn shade(input: EffectInput) -> vec4<f32>`        |
| `src/main.rs`      | `brul::effect!`, сид `phase`, запуск через `run_generated` |
| `src/generated.rs` | подключение сгенерированного вида из `OUT_DIR`             |
| `build.rs`         | единственный вызов `brul::build::app("src/window.brul")`   |

Макрос `brul::effect!` связывает имя `Aurora`, текст шейдера и структуру
параметров. Из полей структуры он выводит раскладку слотов:

```rust
brul::effect! {
    name: "Aurora",
    shader: "aurora.wgsl",
    pub struct AuroraParams {
        phase: f32,
        tint: [f32; 4],
        glow: [f32; 4],
    }
}
```

Имя в правиле стиля должно совпадать с `name` макроса буква в букву: рендерер
ищет описание эффекта по этому имени. Правило в `window.brul`:

```css
.pane {
  effect: Aurora(phase, 0.25, 0.85, 0.65, 0.9, 9, 0.35, 0.22, 0.45);
}
```

Девять аргументов соответствуют полям: `phase`, четыре компоненты `tint` и
четыре компоненты `glow`. Кодоген превращает их в девять замыканий с типом
`Number`, а `EffectDef::pack` раскладывает результат в uniform-слоты. Шейдер
читает их через `effect_param(input, slot)`.

## Анимация

`EffectSpec` из стиля создаётся с `animated: false`; движок не перерисовывает
такие узлы сам, даже если шейдер использует `input.time`. Это отдельный пробел
BRUL-681. Здесь движение демонстрируется вручную: поле ввода вызывает
`setPhase`, биндинг обновляет `phase`, и кадр перерисовывается. Автоматическая
анимация эффекта появится, когда `animated` будет выводиться из шейдера.

## Тесты

`cargo nextest run -p aurora` проверяет три вещи: шейдер проходит компиляцию
naga, аргументы из стиля упаковываются в те же слоты, что и `AuroraParams`, а
после раскладки 640×360 узел из сетки несёт `EffectSpec { name: "Aurora" }` и
занимает ячейку с ненулевой площадью.
