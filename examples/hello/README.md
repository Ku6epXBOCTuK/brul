# hello

Приложение-пример: окно, команда хоста, кнопки из кита BRUL. Всё, что нужно
приложению, здесь есть в минимальном виде — этот каталог читают, когда пишут
своё приложение.

## Запуск

Из корня рабочей копии:

```powershell
cargo run -p hello
```

### Бэкенд отрисовки

По умолчанию окно стартует на софтверном пути: он не ищет GPU-адаптер и
показывает первый кадр раньше. Переменная переключает тот же бинарник на GPU:

```powershell
$env:BRUL_EXAMPLE_BACKEND = 'gpu'
cargo run -p hello
```

Значения — `software` (умолчание) и `gpu`; любое другое завершает запуск
ошибкой. В приложении это `WindowConfig.backend`, который задаётся до
`run_generated`. Сравнение старта двух бэкендов описано в
`docs/dev/benchmarks.md`.

## Что внутри

| Файл               | Роль                                                         |
| ------------------ | ------------------------------------------------------------ |
| `src/window.brul`  | окно, разметка, скрипт, темы                                 |
| `src/main.rs`      | хост с командой `greet`, сиды и запуск через `run_generated` |
| `src/generated.rs` | подключение сгенерированного вида из `OUT_DIR`               |
| `build.rs`         | единственный вызов `brul::build::app("src/window.brul")`     |

`src/generated.rs` не пишется руками: `build.rs` собирает окно из `window.brul`
и кладёт `view.rs` в `OUT_DIR`, а модуль подключает его одной строкой. Имя окна
задаёт имена сгенерированного: окно `Hello` даёт `generated::hello_view`,
`generated::windows()`, `generated::script()`, `generated::names()` и
`generated::ThemeId`.

Команда хоста объявляется атрибутом `#[command]` — первым аргументом идёт хост,
остальные приходят из скрипта. `host!` перечисляет команды, которые видит
`window.brul`:

```rust
#[command]
fn greet(host: &mut HelloHost, name: &str) -> Result<Value, brul::Error> { ... }

host! { HelloHost: greet }
```

Переменные, которые нужны окну до первого клика, объявляются сидами, а не `let`
в скрипте: `let name = "world";` рядом с сидом `name` — ошибка повторного
объявления.

Кнопки берутся из кита BRUL:

```brul
<use>
    import Button from "brul:button";
</use>
```

`brul:` — имя файла в каталоге `kit/` самого BRUL, а не путь рядом с
приложением. Кит встраивается в кодоген при сборке, поэтому каталога `kit` у
приложения нет, и его правки видны без копирования файлов.

## Зависимость от BRUL

`hello` лежит внутри рабочей копии BRUL, поэтому это член workspace и берёт
зависимость из корня: `brul = { workspace = true }` — и в `[dependencies]`, и в
`[build-dependencies]`. Путь живёт в `[workspace.dependencies]` корня, а
`cargo autoinherit` возвращает запись именно к такому виду.

Приложение вне рабочей копии наследования не имеет и пишет путь явно:

```toml
[dependencies]
brul = { path = "../brul" }

[build-dependencies]
brul = { path = "../brul" }
```

Обе секции обязательны: `build.rs` — отдельная сборка со своими зависимостями.

## Тесты

`cargo nextest run -p hello` прогоняет команду хоста и раскладку окна: вид
строится через `generated::hello_view` и укладывается в 420×240 через
`brul::gui::WidgetTree`. Тест раскладки нужен, чтобы правка `window.brul` ловила
вылезший за окно вид, а не проявлялась глазами.
